## Exact runtime APIs

Installed source is canonical. Module for all of the following: **Voxel**.

### A. World actor / runtime owner

- Class: `AVoxelWorld` : `AVoxelWorldInterface`, `IVoxelEditorDelegatesInterface`
- Header: `Source/Voxel/Public/VoxelWorld.h`
- Voxel size: `float VoxelSize = 100` (cm)

### B. Runtime voxel data / coordinates

World ↔ voxel (`AVoxelWorld`):

- `FIntVector GlobalToLocal(const FVector& Position, EVoxelWorldCoordinatesRounding = RoundToNearest) const`
- `FVoxelVector GlobalToLocalFloat(const FVector& Position) const`
- `FVector LocalToGlobal(const FIntVector& Position) const`
- `FVector LocalToGlobalFloat(const FVoxelVector& Position) const`

Density / material (`UVoxelDataTools`, `VoxelTools/VoxelDataTools.h`):

- `GetValue(float& Value, AVoxelWorld* World, FIntVector Position)`
- `GetInterpolatedValue(float& Value, AVoxelWorld* World, FVector Position)`
- `SetValue(AVoxelWorld* World, FIntVector Position, float Value)`
- `GetMaterial` / `SetMaterial`

### C. Destructive sphere / crater

`UVoxelSphereTools` — `VoxelTools/Gen/VoxelSphereTools.h`

C++ crater overload:

```
static void RemoveSphere(
    AVoxelWorld* VoxelWorld,
    const FVector& Position,
    float Radius,
    TArray<FModifiedVoxelValue>* OutModifiedValues = nullptr,
    FVoxelIntBox* OutEditedBounds = nullptr,
    bool bMultiThreaded = true,
    bool bConvertToVoxelSpace = true,
    bool bUpdateRender = true);
```

Also: Blueprint `RemoveSphere` / `RemoveSphereAsync` (latent + `FOnVoxelToolComplete_WithModifiedValues` callback).

Impl: `FVoxelSphereToolsImpl::RemoveSphere` → `SphereEdit<false>`. Geometric. **No Rand** in that path.

### D. Additive fill

Same header: `AddSphere` / `AddSphereAsync` (same parameter pattern as RemoveSphere). Impl `SphereEdit<true>`.

Density fill: `SetValueSphere(..., float Value, ...)`.

### E. Height / surface-ish query

No dedicated “height at XY” in the data tools used for this spike.

Closest surface-ish helper: `UVoxelDataTools::FindClosestNonEmptyVoxel(FVoxelFindClosestNonEmptyVoxelResult&, AVoxelWorld*, FVector Position, bool bReadMaterial=true, bool bConvertToVoxelSpace=true)`.

### F. Bounds

Sphere tools fill optional `FVoxelIntBox& EditedBounds` / `OutEditedBounds`.

### G. Render update

If `bUpdateRender`: `GENERATED_TOOL_CALL` → `FVoxelToolHelpers::UpdateWorld` → `World->GetLODManager().UpdateBounds(Bounds)` (dirty **those** bounds, not the whole world).

If `bUpdateRender=false`: data only; caller must update later (`UVoxelBlueprintLibrary::UpdateBounds`).

### H. Collision update

After mesh section update, `UVoxelProceduralMeshComponent::UpdateCollision()` (async Chaos cook) and optionally `UpdateNavigation()` → `FNavigationSystem::UpdateComponentData(*this)` on **that component**. Scope is the edited chunk/mesh component, not `RebuildAll`.

### I. Async

- Sync: `RemoveSphere` / `AddSphere` / `SetValueSphere`
- Async: `*Async` variants; game-thread callback `FOnVoxelToolComplete_WithModifiedValues`; Blueprint latent `FLatentActionInfo`
- `bMultiThreaded` parallelizes the **edit write**, independent of `*Async`

### J. Save / serialization

`UVoxelDataTools`: `GetSave` / `GetCompressedSave` / `GetSaveAsync` / `GetCompressedSaveAsync` / `LoadFromSave` / `LoadFromCompressedSave`.

Useful for late-join snapshot experiments. Not selected as the primary crater replication path.

### K. Multiplayer

| --- | --- |
| Free APIs | Sphere/box/data tools, save/load, LOD bounds update |

| TCP MP | `UVoxelMultiplayerTcpInterface::ConnectToServer` / `StartServer` **stubs**: log “only available in Voxel Plugin Pro”, return false |

## Crater API chain

Intended GP path (API-level; **not** PIE-proven this checkpoint):

1. Server deformation request (GP; not implemented).
2. Optional `AVoxelWorld::GlobalToLocal` if not using `bConvertToVoxelSpace`.
3. `UVoxelSphereTools::RemoveSphere(World, Position, Radius, OutModified, OutEditedBounds, bMultiThreaded, bConvertToVoxelSpace=true, bUpdateRender=true)`.
4. Macro locks `FVoxelIntBox`, writes voxel values.
5. If `bUpdateRender`: `UpdateWorld` → LOD `UpdateBounds` (local dirty bounds).
6. Mesh update then component `UpdateCollision` / optional `UpdateNavigation`.

One `RemoveSphere` call with defaults:

| Effect | Yes/No |
| --- | --- |
| Changes voxel values | Yes |
| Triggers render update | Yes (`bUpdateRender=true`) |
| Triggers collision update | Yes, after mesh refresh on affected components |
| Is async | **No** for the sync overload; collision cook may still be async |
| Returns modified bounds | Optional `OutEditedBounds` |

Separate update if render was skipped: `UVoxelBlueprintLibrary::UpdateBounds(World, Bounds)`.

## Event replay feasibility

**EVENT_REPLAY_FEASIBLE** (not bit-identical).

Reason: `RemoveSphere` / `AddSphere` / `SetValueSphere` take Position, Radius, (Value). `SphereEdit` has no random and no time input. Same voxel-space inputs should replay the same density write.

Risks (do **not** claim bit-identical):

- `bMultiThreaded=true` write order
- float density
- async LOD / collision cook timing (visual/phys lag, not the density field itself)

Prefer `bMultiThreaded=false` for replay experiments. Not proven in PIE.

---

## Determinism risks

Same as above. Collision cook is async; Recast may see the new collision later. BuildGrid occupancy is independent and will not auto-update from voxels.

## Nav implications

- Collision / nav notify is **chunk/component-local**.
- UE navigation **may** see changed collision if the voxel mesh is navigation-relevant (`bEnableNavmesh` on section settings; `UpdateNavigation` → `UpdateComponentData`).
- Plugin does not expose a Recast rebuild-all hook as the crater path.
- GP still **must not** rebuild Recast after every crater (cost). Stage 3E: bounded test of one crater vs Recast locality; optional traversability overlay.

Current production path unchanged: `UGP_MovementComponent` Recast when coverage exists, else straight-line. No nav rewrite this checkpoint.

BuildGrid: 200 cm cells. Occupancy independent of voxels.
